# Memo Pimpinan Feature — Design

## Purpose

A lightweight module for drafting a **memo / nota dinas** addressed to a
pimpinan. A `super_admin` types the memo (nomor auto-generated, addressee,
subject, body), prints it as an A4 nota-dinas document, and physically takes
the printout to the pimpinan for a wet-ink signature and a hand-written
disposisi. `pimpinan`-role users can open and read memos in the app but
cannot create or change anything.

There is **no in-app signing, no status/approval workflow, and no response
field** — the pimpinan's response is written by hand in a blank box on the
printout and never re-entered into the system.

## Scope

- Standalone module. No relation to E-Invoice / E-Kwitansi / RAB / Program
  Kerja PUI / Agenda.
- Access:
  - `super_admin` — full CRUD (list, create, edit, delete, print).
  - `pimpinan` — read-only (list, detail, print). No create / edit / delete.
  - All other roles — no access.
- Replaces the dead `{ prefix: '/surat', roles: ['super_admin', 'pimpinan'] }`
  rule in `middleware.js` (a route that was never built) with a `/memo` rule.

## Data Model

### Table `memo`

```sql
CREATE TABLE memo (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  nomor        varchar(50) UNIQUE NOT NULL,   -- auto: MEMO/2026/09/0001
  tanggal      date NOT NULL DEFAULT CURRENT_DATE,
  kepada       text NOT NULL,                 -- nama/jabatan pimpinan
  dibuat_oleh  text NOT NULL,                 -- display name, captured at create
  perihal      text NOT NULL,
  isi          text NOT NULL,
  created_at   timestamptz NOT NULL DEFAULT now(),
  updated_at   timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_memo_tanggal ON memo(tanggal);
```

### Numbering

`nomor` is auto-generated by a `BEFORE INSERT` trigger
`generate_memo_number()`, a byte-for-byte copy of `generate_kwitansi_number()`
(migration `20260803010000_create_kwitansi.sql`) with the prefix changed to
`MEMO/` and the sequence source table changed to `memo`. Format
`MEMO/YYYY/MM/NNNN`, per-month `pg_advisory_xact_lock` to keep concurrent
inserts from colliding on a sequence number. The client never sends `nomor`.

### `updated_at`

A `BEFORE UPDATE` trigger `set_memo_updated_at()` (same as
`set_kwitansi_updated_at()`).

### RLS

`ENABLE ROW LEVEL SECURITY`; single policy allowing only
`auth.role() = 'service_role'`. Matches `kwitansi` / `rab` /
`program_kerja_pui` — the per-role gate lives in `middleware.js`, not RLS.

## Access Control

### `middleware.js`

- In `ROLE_RULES`, replace
  `{ prefix: '/surat', roles: ['super_admin', 'pimpinan'] }`
  with
  `{ prefix: '/memo', roles: ['super_admin', 'pimpinan'] }`
  (page-level gate — both roles may reach `/memo*`).
- Add an API gate alongside the existing per-prefix API checks (the block
  that already handles `/api/kwitansi`, `/api/rab`, etc.):
  - `GET /api/memo*` → allowed for `super_admin` and `pimpinan`.
  - Any non-GET method on `/api/memo*` → `super_admin` only (403 otherwise).
  Follows the same `request.method === 'DELETE' ? [...] : [...]` shape
  already used for `/api/kritik-saran` and `/api/saran` in this file.

### Pages

Client-side, `useCurrentUser()` (`lib/hooks/useCurrentUser.js`) provides
`isSuperAdmin`. The list and detail pages render "Tambah Memo", "Edit", and
"Hapus" only when `isSuperAdmin` is true; `pimpinan` sees "Lihat" and
"Cetak" only. The `/memo/create` and `/memo/[id]/edit` pages redirect to
`/memo` once `useCurrentUser()` resolves and `isSuperAdmin` is false (so a
`pimpinan` who types the URL directly doesn't fill a form that would 403 on
save). All of this is UX only — the real enforcement is the middleware API
gate above.

## API Routes

Service-role backed, no self-contained role check (protection entirely via
`middleware.js`), matching the `kwitansi` / `rab` convention. Slug in the
`[id]` route is the memo `nomor` turned into a URL-safe slug via
`nomorToSlug` / `slugToNomor` (`lib/utils/format.js`), same as
`/api/kwitansi/[id]`.

- `GET /api/memo` — list all memos, `order by created_at desc`.
- `POST /api/memo` — create. Body: `{ tanggal, kepada, dibuat_oleh, perihal,
  isi }`. Server trims strings and rejects empty `kepada` / `perihal` /
  `isi`. `nomor` comes from the trigger. Duplicate-number errors surfaced
  via `friendlyDbError(err, { duplicateLabel: 'Nomor memo' })`.
- `GET /api/memo/[id]` — one memo by `slugToNomor(id)`.
- `PUT /api/memo/[id]` — update `tanggal`, `kepada`, `dibuat_oleh`,
  `perihal`, `isi`. `nomor` is never changed after creation.
- `DELETE /api/memo/[id]` — delete.

## Pages & Routing

Mirrors the E-Kwitansi page structure.

| Route | Purpose |
|---|---|
| `/memo` | List: table of Nomor, Tanggal, Kepada, Perihal, Dibuat Oleh, actions. Text search over nomor / kepada / perihal / dibuat_oleh. "Tambah Memo" button (super_admin only). |
| `/memo/create` | Create form. |
| `/memo/[id]` | Detail view — the memo rendered read-only, plus Cetak / (Edit / Hapus for super_admin) buttons. |
| `/memo/[id]/edit` | Edit form, same shape as create, pre-filled. |
| `/memo/[id]/print` | A4 nota-dinas print view. |


## Form Behaviour (Create / Edit)

Fields, in order:

- **Tanggal** — date, required, defaults to today.
- **Kepada** — `<select>` populated from `PIMPINAN_LIST`. Selecting
  "Lainnya (Input Manual)" reveals a free-text input. On edit, a stored
  value not in the list pre-selects "Lainnya" and pre-fills the manual
  input. Same manual-fallback pattern as the agenda form's
  `pimpinan_select` / `pimpinan_manual`.
- **Perihal** — text, required.
- **Dibuat oleh** — text, required. On the create form it is pre-filled
  with `useCurrentUser().displayName` and remains editable. On the edit
  form it shows the stored value.
- **Isi Memo** — textarea (≈8 rows), required.

Validation before submit: `kepada` (or its manual value), `perihal`,
`dibuat_oleh`, and `isi` all non-empty. Errors shown in the same
`.error-msg` block pattern used across the app's modals/forms.

Create and edit are full-page routes (`/memo/create`, `/memo/[id]/edit`),
not modals — matching E-Kwitansi and RAB.

## Print Page (`/memo/[id]/print`)

Follows the established print-page conventions shared with the
E-Invoice / E-Kwitansi / RAB print pages (including the mobile
`overflow-x: auto` wrapper + `@media print { overflow: visible }` fix and
the A4 `@media print` block that hides `.no-print`, nav, sidebar, topbar,
etc.).

Layout (A4 portrait):

- **Kop** — logo + `brand_name` from `/api/app-settings` (same fetch as
  every other print page), with a thin rule beneath.
- Centered title **`NOTA DINAS`** and, under it, `Nomor: {nomor}`.
- A labelled block, left-aligned:
  - `Yth.      : {kepada}`
  - `Dari      : {dibuat_oleh}`
  - `Hal       : {perihal}`
  - `Tanggal   : {formatDate(tanggal)}`
  - thin rule beneath.
- **Isi** — `{isi}` rendered with preserved line breaks
  (`white-space: pre-wrap`).
- A fixed closing line: *"Demikian disampaikan, atas perhatian dan arahan
  Bapak/Ibu diucapkan terima kasih."*
- **Catatan / Disposisi Pimpinan:** — a bordered empty box, ~120px tall,
  for the pimpinan's hand-written response.
- **Signature area** — two columns:
  - left: `Dibuat oleh,` … blank … `( {dibuat_oleh} )`
  - right: `Menyetujui,` … blank … `( {kepada} )`
- **Footer** — `Dokumen ini digenerate secara elektronik melalui sistem
  SIMDIR`, matching the E-Kwitansi print footer.

The on-screen `.no-print` controls bar has "Kembali" and "Cetak / Simpan
PDF" buttons, same as the E-Kwitansi print page. No print-time toggles
(the disposisi box and both signature blocks always print).

## Migration

`supabase/migrations/20260910000000_create_memo.sql` — `CREATE TABLE memo`,
`generate_memo_number()` + its trigger, `set_memo_updated_at()` + its
trigger, `ENABLE ROW LEVEL SECURITY` + the service-role policy. Header

updated (it is already stale vs. migrations for several tables — migrations
are the source of truth).

## Out of Scope (explicitly, per YAGNI)

- No in-app signing / signature pad / stored signatures.
- No status or approval workflow (draf / menunggu / ditandatangani /
  dikembalikan).
- No "needs my signature" queue for pimpinan.
- No response / jawaban / disposisi **data** field — the printout's blank
  box is the only place it exists.
- No notifications, no lampiran/attachment, no tembusan (cc) list.
- No `created_by` FK or audit log — `dibuat_oleh` is a plain editable
  display-name string.
- No linkage to any other module.
